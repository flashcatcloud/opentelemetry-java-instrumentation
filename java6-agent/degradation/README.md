# Java 6 runtime degradation and OpAMP

This module extends the existing Java 6 compatibility distribution. It uses that
branch's SDK and HTTP sender, with official OpAMP protobuf messages generated by
pinned protoc 3.3.0 and a Java 6-compatible protobuf runtime. It does not load the
Java 8-only OpAMP client. `deps.json` and `schema.json` pin inputs by SHA-256.

Enable with JVM properties (without an endpoint, no OpAMP worker is started):

```properties
otel.javaagent.opamp.endpoint=http://n9e.example:17000/v1/opamp
otel.javaagent.opamp.headers=Authorization=Bearer <target-token>
otel.service.name=my-service
otel.resource.attributes=deployment.environment.name=prod
```

The `elastic` remote configuration is compatible with the existing n9e-plus
`plus/opamp` handler and store:

```json
{"deactivate_all_instrumentations":"true","send_traces":"false","send_metrics":"false","send_logs":"false","opamp_polling_interval":"5s"}
```

The four booleans are required (JSON booleans or strings). Polling interval is
optional, between 1 and 3600 seconds. Unknown/duplicate fields and invalid
values are rejected, with a FAILED ACK and the previous configuration retained.
A successful configuration is acknowledged immediately; acknowledgments are
retained across failed HTTP requests. The instance ID is stable for the process.

Stopping disables SDK span recording for both cached and newly created tracers
and gates trace, metric and log exporters. Resuming restores the original tracer
configurator and enables the configured exporters without restarting the JVM.
This does not remove injected bytecode or unload instrumentation. Metric/log
collection may continue internally, and already in-flight exports may finish.
Only the HTTP/protobuf remote-config portion of OpAMP is implemented; package
management, restart commands and WebSocket transport are not supported.
Transport/TLS behavior is inherited from the existing compatibility SDK/JVM.

## Build

Run `java6-agent/build-official-candidate.sh` with the existing compatibility
SDK configuration. The script prepares and compiles this module before packaging.
For an incremental build after the existing SDK/tooling artifacts are available:

```sh
python3 java6-agent/degradation/prepare.py
# Inside the same pinned Linux/amd64 JDK 8 container used by the main build:
sh java6-agent/degradation/build.sh
python3 java6-agent/package-official.py --sdk /path/to/opentelemetry-java \
  --output /path/to/degradation-candidate.jar
```

Retrolambda analyzes the existing SDK interfaces together with the module so
interface static/default calls resolve to the existing Java 6 companion classes.
Only module and protocol classes are added to the distribution. Packaging checks
class-file versions and merges SPI registrations; licenses, SBOM and provenance
include the module and protobuf runtime.

## Interoperability regression

Compile `tests/InteropApplication.java` with JDK 8 `javac -source 6 -target 6`,
the actual Java 6 `rt.jar` as `-bootclasspath`, and the packaged agent as `-cp`.
Then run for each target Java executable:

```sh
INTEROP_JAVA=/path/to/java \
INTEROP_AGENT=/path/to/degradation-candidate.jar \
INTEROP_CLASSPATH=/path/to/test-classes \
python3 java6-agent/degradation/tests/run.py /path/to/n9e-plus
```

The runner copies the unmodified n9e-plus handler/store into an isolated Go test
module and runs `go test -mod=mod -race -v -count=1 -timeout=180s .` against a
real agent JVM with `-Xverify:all`. No shared n9e instance is modified.
It verifies two stop/resume cycles in one process, applied configuration hashes,
three OTLP signals, cached/new tracer recording, continued business HTTP
requests, lost ACK retry, HTTP 503 recovery, rejection of invalid configuration,
one instance identity, and default-off operation. A native Linux x86_64 host is
required for Oracle Java 6u45; an SSH launcher can reverse-forward the isolated
local test server and substitute the remote agent/class paths.
