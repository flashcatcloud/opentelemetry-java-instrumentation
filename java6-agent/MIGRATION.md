# Official Agent Java 6+ migration

This document records the expanded user-approved scope. The active goal UI still
contains the initial narrower wording because the available goal tool cannot edit
an active objective. The later user instructions below govern implementation and
completion; the original scope alone is not sufficient for delivery.

The final distribution must use official Agent loading, Muzzle compatibility checks,
helper injection, Instrumenter APIs and component implementations. It must not
select a handwritten Java 6 engine and a separate official Java 8 engine.
Upstream sources are pinned to instrumentation v2.32.0 and SDK v1.66.0.
Compatibility overlays record original source hashes and generated patches.

## Acceptance scope (user confirmed 2026-10-14)

- One JAR, unchanged business code, real Oracle JDK 6u45, Java 8 and Java 17.
- HTTP, Servlet/Tomcat, JDBC (MySQL and Oracle), Redis, old and modern Dubbo.
  Include Apache Dubbo 2.7 and representative 3.x releases in the verification
  matrix, in addition to legacy com.alibaba Dubbo 2.5/2.6.
- Old Dubbo 2.5/2.6 retains only extensions needed beyond upstream support,
  including asynchronous propagation and span completion.
- Broaden coverage using official modules: Spring MVC, common HTTP clients,
  JDBC pools, Jedis/Lettuce, executors, Kafka, RabbitMQ, MongoDB,
  Elasticsearch and gRPC. The list is an implementation/testing queue, NOT a
  declaration that these modules already work.
- Verify each library on JVM versions supported by the library itself; distinguish
  an agent incompatibility from an agent-free application incompatibility.
- Test real propagation and parentage, asynchronous completion, errors,
  concurrency/context restoration, and OTLP export/failure behavior.
- Remove replaced handwritten implementations after official replacements pass.
- Publish a JAR, SHA-256, usage instructions, exact supported-version matrix and
  evidence. Do not describe compilation or successful startup as full support.

## Current migration state

The existing delivery JAR predates the official component migration. The separate
`build/official-loader-candidate.jar` now uses upstream AgentInstaller, internal
class-loader support, Muzzle, and official HTTP/JDBC/Servlet/Tomcat modules, with
runtime evidence below. It has not replaced the release artifact or the continuous
PoC containers. Redis migration is in progress; an initial runtime test exposed
missing Redis error status and duplicate pipeline commands. These failures must
be fixed and retested before declaring Redis migrated. The candidate still carries
unused prototype classes; deleting replaced implementations and final packaging
remain required. No component may be marked supported from compilation alone.
